# 半 CPU 四策略受控机制对照（2026-10-26）

## 结论

在预注册的两组各 20 作业、同到达的合成 Medium 场景中，八格全部完成 20/20；独立逐轮验证均通过。JOINT-G 对 SIA-P 的平均 JCT 分别改善 **7.47%** 与 **11.53%**，对固定 Sia GPU 意图的 SIA-AUX 分别改善 **2.19%** 与 **9.22%**。SIA-AUX 自身对 SIA-P 也分别改善 **5.40%** 与 **2.55%**，说明此固定响应模型中的辅助资源分配机会确实能转化为部分端到端收益。

但 JOINT-G 相对 SIA-AUX 的净收益**主要来自等待和 checkpoint 缩短，而不是总有效训练时间缩短**；完整策略还同时改变准入、服务承诺、GPU 几何与同分选择。因此不能把 JOINT-G 的全部改善归因于“联合 CPU/RAM 配额优化”，也不能宣称真实集群性能提升。两组固定状态的无损资源转移均依赖 E-legacy 裁剪边界，运行中分子 CPU 坐标越界的选中列占 39.6%–47.9%。

## 机制归因：训练速率机会存在，但 JOINT-G 净收益主要不是训练段

同一组全部作业的 `ΣJCT = Σ等待 + Σcheckpoint + Σ有效训练`。下面是 **SIA-AUX 减 JOINT-G** 的总秒数；正数有利于 G，负数表示 G 更慢：

|负载|等待差|checkpoint 差|有效训练差|ΣJCT 差|
|---|---:|---:|---:|---:|
|original20|+3840|+1245|−3344|+1741|
|holdout20|+11340|+945|−3458|+8827|

JOINT-G 两组的等待总量均为 1200 秒，即每个同到达作业的首轮 60 秒；SIA-AUX 分别为 5040/12540 秒。G 的训练总时间却更长。这说明当前 G 对强辅助基线的改善主要是选择谁何时运行及减少重启/延迟的综合效果，**不是证明其 CPU/RAM 配额本身提高了总训练速率**。G 的 restart 分别为 36/45，低于 AUX 的 70/61；wasted GPU-seconds 分别 4735/4435，低于 AUX 的 6425/6220。

SIA-AUX 是更直接的辅助资源证据：相对 SIA-P，original20 的训练总秒数减少 4070，holdout20 减少 2239，且实际非比例 CPU 选中列为 660/1252 与 780/1396。SIA-AUX 的 `rho>1` 选中列分别 91/1252、54/1396，说明优化器确实选过加速配额；但逐轮选中列受不同作业存活时长影响，不能把这个频数当作速度提升的因果估计。原固定状态的离线无损重分配见证及其裁剪依赖，详见 `HALF_CPU_OFFLINE_PREFLIGHT_DECISION_20261026.md`。

JOINT-G 非比例 CPU 选中列为 779/1288 与 938/1438；`rho>1` 为 149/1288 与 108/1438。B3-FREE 的 `rho>1` 频数更高（227/1254、212/1394），但 JCT 两组均不及 G，支持“局部选择更多加速点不保证端到端 JCT 更好”。B3-FREE 等待分别 7260/7740 秒、restart 95/97，均高于 G；两者的候选剪枝、同分规则及 L2 也不同，不能只归因于一个机制。

逐作业影响并不均匀。G 对 P 的最大正贡献为 original20 `bert-28` 提前 1737 秒（净改善的 27.6%），holdout20 `bert-15` 提前 7457 秒（净改善的 65.8%）；去掉这一个作业的**诊断性**改善率仍为 5.66%/4.36%，但不得替换全 20 作业主结果。G 对 AUX 的 original20 净优势几乎完全由 `bert-28` 驱动（1737/1741 秒，去除后仅 +0.01%）；holdout20 的 `bert-118` 占净优势 79.1%，去除后 +2.12%。G 对 AUX 仍分别有 9 个作业退化；例如 original20 的 `deepspeech2-21` 晚 1258 秒，holdout20 的 `deepspeech2-123` 晚 1208 秒。

## 正确性与模型边界

- 八格原始完成事件独立复算均为 20/20；验证器逐条核验 8 份压缩轮次日志中的训练进度单调与单次 `rho`、当前 R0 响应、完整 checkpoint 锁、每节点 GPU/CPU/RAM 容量和 JCT 汇总。所有验证 `valid=true`，容量/执行违规均为 0；所有轮次求解状态均为各策略的成功状态，无 fallback。原始输入及运行 SHA-256、逐作业 JCT/时间、求解状态和验证计数见 `comparison_summary.json` 与各格 `independent_validation.json`。
- 资源小时是配额乘实际持有时间，不是 CPU 真正忙碌或 RAM 工作集。JOINT-G 的 CPU 饱和而 GPU 空闲节点轮事件为 49/47，B3-FREE 为 109/120；SIA-P/AUX 为 0。该事件是节点轮口径，不等于作业等待秒数，也不能单独判断策略优劣。
- 选中列中，分子 CPU 请求坐标越出原 Synergy 矩阵范围：P 47.7%/47.9%、AUX 42.0%/42.9%、FREE 39.6%/41.2%、G 42.7%/46.5%（original/holdout）。分母 CPU 越界也存在；G 为 223/1288 与 128/1438。E-legacy clipping 是冻结公式的一部分，没有事后修改，但目标硬件的边界真实形状未知；这些收益只在合成跨硬件迁移模型内成立。`rho` 并非等于 1：P 的执行范围 0.6923–1，G 为 0.6923–1.8504。
- 两组数据提供资源竞争和混合敏感性，足以验证“已有公式下能否利用机会”；样本少、同到达、单节点每 GPU 类型、无真实 CPU/GPU 联合测量。它们不足以评价真实 Saturn 性能，也不能识别 placement 与准入相对 GPU/CPU 优化各自的单独贡献。
