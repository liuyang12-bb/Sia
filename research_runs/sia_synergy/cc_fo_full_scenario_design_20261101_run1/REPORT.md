# FULL 相对 FO 的条件优势：辅助资源错配下的弹性 GPU 收缩

SYNTHETIC CROSS-HARDWARE TRANSFER — NOT REAL SATURN PERFORMANCE

## 本轮结论

研究应证明“存在可解释、可重复的适用条件”，无需证明所有负载都巨大获益。上一轮 FULL 比 FO 平均 JCT 低 8.475%，已经是有效的小规模观测；新候选对 FULL 自身的 1.033% 增益是另一种比较，不能混淆。

本轮完成新场景设计及只读离线枚举。没有修改算法、响应、已有源码/报告，没有启动新训练仿真。342 个冻结源文件哈希一致。这里补充的是合法候选机会证据，不是新的 JCT 结果。

最明确的新机会是：**固定 GPU 数量后，FO 即使把整节点 CPU/RAM 都分给一个任务，也可能比减少 GPU、重新集中辅助配额更慢。** 这种缺口只有重新选择 GPU 配置才能弥补，不能用“FO 已经会优化 CPU”消除。

## 先澄清 FO

`cc-joint-residual-capacity-v1/sia-simulator/joint_prototype/clean_ablation.py:75–96`：FO 先在比例候选域按共同目标选 GPU 和服务集合，再冻结 config_id，优化辅助资源。它的第一阶段已经使用比例点的 rho；不能称其完全 CPU 盲，也不能冒称 FO 就是原始 Sia。

FULL 使用同一目标和合法候选，但可以联合选择。当前目标是 SUM_RECIPROCAL_CURRENT_COMPLETION_ETA（同文件286起），不是总训练速率；持续服务、checkpoint、恢复预算仍限制在线切换。本轮没有更改这些语义。

因此，场景需要满足：比例点的配置排序，与优化辅助配额后的配置排序不同。仅有 CPU 敏感任务或辅助资源不足，不足以形成 FULL 对 FO 的增量。

## 新容量方案：保持总预算，改变节点供给结构

各节点始终 2 GPU；CPU 为合成计算单位，RAM 为 GB。总预算始终 4 GPU、12 CPU、250 GB。

|方案|AWS CPU/RAM|DGX-ext CPU/RAM|用途|
|---|---:|---:|---|
|S0 对称|6 / 125|6 / 125|基准负对照，复用原容量|
|S1 CPU 错配|9 / 125|3 / 125|隔离 CPU 分布影响|
|S2 RAM 错配|6 / 187.5|6 / 62.5|隔离 RAM 分布影响|
|S3 交叉错配|9 / 62.5|3 / 187.5|CPU 富集在 AWS、RAM 富集在 DGX；检验 GPU 数量与辅助配额的耦合|

3:1/1:3 是事先规定的单次结构干预，不是按 JCT 搜索出的最优比例。四种方案都在离线计算前记录，零增益方案同样保留。比例点均满足原执行下限 CPU≥1、RAM≥20.83；不以人为不合法资源包削弱 FO。

## 已核验的具体机会

来源是上一轮 NEW_FULL 日志420秒的第一个 CIFAR/BERT 配对；使用当时记录的合法 GPU 候选和归一化 Sia Goodput、冻结 R0、原官方模板、alpha=.5。为研究容量结构，静态枚举中去掉其旧分配几何，**不是**对当时运行作业执行一次无成本切换。

在 S3 中，固定 AWS 节点整包预算9 CPU、62.5GB：

|CIFAR 配置|GPU数|每GPU CPU/RAM|CPU/RAM总量|原归一化GPU Goodput|rho|有效归一化速度|
|---|---:|---:|---:|---:|---:|---:|
|固定GPU后最优配额|2|4.5 / 31.25|9 / 62.5|1.950131|0.618327|1.205819|
|允许弹性收缩|1|9 / 62.5|9 / 62.5|1.000000|1.611957|1.611957|

1 GPU 方案速度提高 **33.6815%**，CPU/RAM 总量不变，另一个节点的 BERT 配置和配额完全不变。减少 GPU 后单卡可用 RAM 和 CPU 上升，补偿了 GPU 原始吞吐损失。这是合法的整体集合 Pareto 速度改善，不是忽略 donor 损失的资源转移。

CIFAR 两个比较点的分子和分母都在源矩阵支持范围内：

- 2 GPU 请求源坐标(2.306253,22.371611)，基准(1.537502,44.743223)。
- 1 GPU 请求源坐标(4.024111,41.792055)，基准(1.341370,41.792055)。
- 没有为该任务添加特定点，9 CPU 是原网格/整节点上界，62.5GB 是原网格。两方法均用已验收残余容量 provider。

BERT 保持 DGX2、每GPU1 CPU/20.83GB，执行 rho=1，但其分子与分母依赖 E-legacy 裁剪。不能说整个组合都在实测支持范围内。CIFAR 的33.68%局部差异不由 BERT 裁剪制造，但 BERT 的速度和机会的全局重要性仍受该合成假设影响。`v2_coverage.json`逐配置记录这一缺口，不删配置、不补 phi、不修改边界规则。

两个必选任务、同一诊断目标“归一化速度之和”下穷举：S0/S1/S2 的联合上界与串行上界相同，S3 联合上界高2.1255%。**这不是实际 FO/FULL 的决策结果**：诊断目标不是完成优先目标，且没有准入、切换成本；不同任务的归一化速度不能当成可相加的真实训练工作量。其用途是提供可行反例和配置排序证据，不能据此报告 JCT 改善。

初版离线脚本误用了历史缩小网格；保留全部初版输出。`precheck_v2.py`改为读取当前 core80_config 的完整网格并加原 build 的8 CPU点，重新枚举，关键结论相同。本报告以 v2 为准。这是诊断脚本校正，算法源码未变。

## 何时能转化为 JCT

对固定剩余工作W、速率v_F/v_J、其他任务不受影响的理想条件：

`JCT节省 = W/v_F - W/v_J - Δ切换延迟`。

本例如果速率比保持不变且启动成本相同，CIFAR 剩余训练时间可低25.1953%。若新方案额外切换延迟为d，必须有旧方案剩余训练时间 `T_F > d/0.251953` 才有净收益。

这只是条件推导。真实 batch/epoch、在线估计、资源释放、checkpoint锁和服务保护会改变轨迹；不能把25.20%直接当作12作业平均JCT预测。预检中两节点、两个必选作业还有 GPU 空闲，也不能宣称已证明12作业持续竞争机会。

## 冻结的后续小规模实验设计

保留原12个真实作业（6 CIFAR、6 BERT）、原batch、GPU demand、训练工作量和映射。只改本表容量及一个明确的到达压力对照；禁止替换长作业或按结果重选任务。

1. 主比较：S0/S1/S2/S3 × FO/FULL，Medium，沿用COMPACT12到达，共8格。S1/S2即使零收益也运行并报告，避免只展示交叉错配。
2. 机制负对照：S3 × FO/FULL，Neutral，共2格，分离资源响应与其他调度差异。
3. 持续竞争检查：S3 × FO/FULL，Medium，12作业同时到达，共2格；任务顺序和总工作量不变。与COMPACT分开报告，不混成独立随机重复。

共12格，每格12作业，60秒/6000轮、同样seed_profiles(1,8)、求解器参数、目标、checkpoint、恢复规则；内存2GiB/磁盘5GiB，独立进程串行，新目录。没有80作业，没有预测纠偏，没有参数搜索。

仅仅同一源码运行还不够：`core80.py:172–190` 会重新生成3CPU/62.5GB每GPU容量，不能只改 JSON 就认为新容量生效。下一步运行器须在构造前通过显式实验容量入口传入这四种预算，验证 simulator、policy.node_capacities、scheduler.nodes、候选provider和执行审计完全一致；不得实验途中改容量。这是运行适配验收项，本轮未实施。

## 评价与论文边界

主指标是全12作业完成后的配对平均JCT，保留中位/P95/P99/makespan、逐作业改善/退化、等待/训练/checkpoint、restart/资源小时和裁剪。删失时报告完成率和删失时间，不拿完成者均值宣布胜出。

重点量化：FULL相对FO的净总JCT差；最大单任务贡献；去掉最大贡献者的诊断性均值；每次GPU配置变化是否真实兑现；CPU/RAM优化共享收益不能全部算联合GPU收益。Neutral与Medium比较用于判断响应耦合，不是完全隔离的单机制因果证明。

可检验的论文主张：**在节点辅助资源与GPU配置不匹配、优化后的资源响应改变GPU配置排序、且机会足以覆盖重配置成本时，联合选择能突破串行GPU冻结的性能上限。** 没有必要主张所有负载都巨大改善；同时必须报告该条件何时不成立。

本轮停止在设计与离线核验。新实验配置、作业文件和机器可读方案在本目录；尚无新的FO/FULL JCT结果。
