# L2 状态机约束与测试界

本论证先于新模式和红绿测试。仅针对有限 N≤3 的 Stage2B 机制测试，不证明无限到达系统稳定性。

状态是 ready FIFO、已签发服务承诺 H、真实 checkpoint 锁 L、累计 productive seconds、签发序号。作业只有未到达、ready、承诺、完成四种状态。L 是正交属性，不冒用 checkpoint 表达 H。

每个调度边界先处理完成和真实训练计数；同边界新到者按 arrival/source row 入队，然后到期承诺按签发序号入队。旧 ready 的相对顺序不变。每次求解和队列更新作为一份事务，异常不签发新承诺。

假设：(a) 有限作业、每个作业在自己的当前单元单独可行；(b) 所承诺几何在服务期间仍合法且资源稳定；(c) 延迟只在服务开始时重置一次且≤D_bar；(d) 延迟后训练时间每真实秒累计一秒且执行率为正，提前完成则退出；(e) 正常求解每轮得到可行性证明；(f) 周期为Δ。求解失败、零率、未知候选或不可行承诺均显式停止正常保证路径。

单服务段：启动后≤D_bar进入训练，累计Q后在下一边界退出，因此签发到退出≤L=D_bar+Q+Δ。用≤而非严格<容纳浮点边界。真实 checkpoint 不能提前释放，但在没有服务期间重启时它已在同一D_bar内结束。epoch不能重置服务量；有限epoch取整可能带来进度残差，不改变productive时间累计。

排空：当ready队首与已有承诺不共存，禁止所有新签发和续签。现有承诺最迟在L内全部退出。队首单独可行，下一边界一定被强制接纳，不允许小作业无限回填。真实锁无服务记录视为状态错误，不临时发明无限保护。

等待：固定一个已ready的j。此时最多N-1个ready前驱；每次正常准入至少移走队首或排空。已获得服务的前驱退到j之后；新到作业也不能越过j。每个前驱至多消耗一次L排空等待再被移走。初始已有承诺再宽松计一次L，随后j自身至多一次L排空。故从入队边界到签发，采用保守W_alloc=(N+1)L；首次到达至入队再加Δ。从到达至首次有效训练保守W_first=Δ+(N+1)L+D_bar+Δ；多出的末尾Δ用于离散观测正进度，不用于延长实验窗口。重复服务从再次入队应用同一界。没有使用JCT或未来完成时长排序。

本界刻意宽于精确情况；不是仅引用Stage2A的(2N+2)L。验证必须检查状态不变量（不越队、不续签排空、服务无延迟记账、持有几何不变），并使用独立小型状态枚举/确定性fixture反例检查。最终完成还需有限工作量、正执行率下界与无进度回滚，短测试不冒充全任务完成证明。

冻结测试上限：状态机fixture最多30轮（Δ60，Q300，D≤250），真实三作业重复服务最多30轮；真实unseeded BERT完整链路固定(60,60,60,1)，不按结果延长。故障fixture仅1–3作业/≤3次决策。原71项测试保持原文与原界。未完成全训练的机制fixture仅报告有限服务/进度，不报虚构JCT。
