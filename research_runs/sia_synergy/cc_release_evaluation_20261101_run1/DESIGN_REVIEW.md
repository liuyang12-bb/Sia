# 完成事件评价 V1：独立只读设计与代码复核

本复核仅阅读源码、设计和已有测试输出；未修改调度代码、未启动仿真。复核对象为 `cc-joint-release-evaluation-v1` 的 `release_evaluation.py`、`clean_ablation.py` 提交前 hook 与 `bundle_adaptation.py` 新主目标验收。历史源码与产物不变。

## 1. 总体判断

作为保留旧决策的有限提案重排器，当前设计可以用于小规模正确性与完整训练验证。它以当前所有已到达作业的预测完成时间之和比较三个方案，明确计入让出方的延后。它不是全局最优调度器，也不是对后续真实策略的精确模拟。不能由“预测不劣于本轮旧方案”推出闭环 JCT 必然改善。

实际选择发生在 `clean_ablation.py` 的最终求解后、服务账本更新前；随后仍执行完整资源审计及当前候选域检查。FO 的新方案域保持旧 FO 本轮 GPU config 不变；FULL 使用相同过滤后的完整合法域。旧模式未安装 hook 时保持原路径。

## 2. 发现并已反馈修复的初始时刻问题

最初实现中，预测器在 t=0 即尝试启动队列作业，但这些作业并不在真实提交的 initial 集合。新方案腾出余量时，这会错误预测等待者立即开始，而真实最早应在下一次 60 秒调度启动。

复核反馈后代码已改为 `while queue and t > 0`，并在初始存在等待队列时增加下一周期边界事件。新增边界测试通过记录在 `green_boundary_review.log`；复核时该日志为 14 tests PASS。后续完成事件本身仍记录周期内真实预测完成时刻，资源复用等到周期边界。

## 3. 会直接限制本轮结论的机制边界

**未知等待者可能使资源释放评价在主要排队阶段无法启用。** 当前 `get_goodput_fn` 需要已观测训练模型；持续服务规则不驱逐已启动任务。因此 ready 队列中的任务通常尚未得到有效训练，缺少 ETA。为避免虚构 ETA，整个预测器正确地 abstain。已有 420 秒同状态结果明确列出 `bert-54`、`cifar10-2` 为未知等待者。

当 ready 全部排空，预测器才能比较所有已观测任务；但其后续规则又冻结存活任务的配额直到完成。因此没有等待者时，目标实际上等于当前服务集合的静态 ETA 和，完成释放并不为后续作业产生预测收益。这是 V1 的适用范围限制，不能在报告中把潜在 JCT 改善统一解释为“资源释放收益”。

必须统计：有等待者的总轮数、因未知等待者 abstain 的轮数、成功评价且队列非空的轮数、三个提案各自被选次数，以及等待者预测时间变化对总分的贡献。若成功评价且队列非空为 0，应明确写“本轮仅验证 donor/receiver 完成时间评价，未验证真实排队阶段的资源释放决策能力”。不得为了触发该分支额外 seed、补假 ETA 或改变持续服务。

## 4. 剩余设计限制与必要披露

- 仅三个 proposal。旧倒数 ETA、静态 ETA 最优、合法旧几何混合方案未覆盖所有组合；未知的更好方案可能根本未生成。
- 当前服务集合来自旧准入和旧方案，新评价不改选任务集合。该任务选择混杂被控制，但不能声称本轮实现了全局完成时间准入。
- 预测固定当前学习模型、batch、rho 和 remaining work；实际 epoch、梯度模型与后续 batch 可以变化。局部预测证据不能替代完整训练结果。
- 存活作业未来 GPU/CPU/RAM 固定，不产生未付费重配置；也因此低估了资源释放后给存活作业扩容的能力。
- 预测队列使用共同 FIFO、合法当前候选和最早完成配置；这是两方法共享的评价假设，不是未来 FO/FULL 真实决策重放。
- FO 固定 GPU 意图内重新评价，不得拿 FULL 域的旧分配作为必达下界；现有跨域验收修复需继续保留。
- `result.scheduling_objective` 仍保存旧 reciprocal utility 时，必须标注仅为提案诊断。新主目标由 `completion_event_objective_seconds` / `release_completion.selected.sum_completion` 提供。
- UNKNOWN_MODEL 或 NO_CONTINUATION 不应在结果状态上冒充成功完成新目标评价；即使保留旧合法方案，也应明确记录 abstain 状态及原因。
- 每轮新增一次静态 ETA MIP 和至多三个预测器调用，有在线开销；训练模拟不自动把墙钟求解时间计入 JCT，报告需分开呈现。

## 5. 本轮实验的解释边界

旧/新 FO/FULL 必须共享同一 COMPACT12 输入、初始画像设置、容量、Medium R0/E-legacy、6000 轮上限和真实训练执行函数。新目标属于算法改动，可以评价，但不能把重跑差异误称为纯验收修复。

若新规则减少静态 ETA 却恶化 JCT，优先检查预测误差、早期 abstain、有限 proposal、被固定的服务集合与未来资源重分配缺失；不应据结果调整负载或响应以制造改善。若均值改善但尾部恶化，必须逐作业报告，不删长作业。
